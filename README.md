# OpsWatch 발표 제출본

가상의 국방망 인트라넷입니다. 구형과 패치 사이트에서 당직 연락망, 로그인·비밀번호 정책, 관리 설정, 호스트 진단을 비교합니다. **로컬 전용**이며 실제 계정·설정·인사정보를 넣지 않습니다.

로그인 후 부대원 조회, 게시판, 결재, 일정, 공지 관리와 내 정보 수정 기능을 이용할 수 있습니다.


## 실행

Python 3.10 이상이 필요합니다. 프로젝트에 `.venv`가 있으면 자동으로 사용하며 활성화할 필요는 없습니다. `.venv`가 없고 현재 Python에 맞는 Django 버전이 설치돼 있지 않으면 `python -m pip install -r requirements.txt`를 한 번 실행하세요.

```powershell
python manage.py runserver
```

두 SQLite DB의 마이그레이션과 구형 발표 데이터 준비는 실행할 때 자동으로 처리됩니다.

- 구형: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- 패치: [http://127.0.0.1:8001/](http://127.0.0.1:8001/)

실행한 터미널에서 `Ctrl+C`를 누르면 둘 다 종료됩니다. SQLite 파일(`legacy.sqlite3`, `patched.sqlite3`)과 세션 쿠키는 사이트별로 분리됩니다.

패치 사이트에 로그인해 진단을 시연하려면 발표 계정을 한 번 발급하세요. 서버 실행 자체에는 필요하지 않습니다.

```powershell
python manage.py create_operator presenter --name "김준호" --rank "중사" --diagnostics
```

구형 포트를 바꾸려면 `--legacy-port`를 지정하세요. 패치 사이트는 리다이렉트 대상인 `8001`을 사용합니다.

이전 Docker 실습 서버가 `8000`을 점유하면 `docker stop opswatch-lab-web-1`로 그 컨테이너만 종료한 뒤 다시 실행하세요.

발표 때 구형 사이트로 먼저 접속하세요. 유지보수 계정으로 로그인한 뒤 **호스트 진단**에서 텍스트를 입력하고 `Enter` 또는 **진단 요청**을 누르면 패치 사이트로 자동 이동합니다. 입력값은 전송하거나 실행하지 않으며, 패치 사이트는 별도로 로그인합니다.

패치 사이트는 `/admin/setting`을 제공하지 않습니다. 관리자도 `404`를 받습니다. 진단은 저장된 점검 기록 조회이며 어느 쪽도 실제 `ping`을 실행하지 않습니다.

## 발표 범위와 슬라이드 정정

| 슬라이드 | 구현에 맞는 설명 |
| --- | --- |
| 1·4·13 | 일반 접속은 구형에 그대로 남습니다. 제출본에서 자동 전환되는 시점은 **구형 호스트 진단 요청을 제출할 때**입니다. 사고 탐지·감사 로그는 가상 시나리오입니다. |
| 7·8 | 구형 연락망에는 콘솔 ID가 표시되고 로그인 횟수 제한이 없습니다. 약한 비밀번호 예시는 구형 시드 계정 기준입니다. |
| 9 | 공지 제목은 **당직 인수인계**이며 포털 관리자가 아닌 유지보수 계정에 보입니다. `/admin/setting` 자체는 로그인 없이 **가짜 예제 JSON**을 반환하며 실제 DB 설정을 읽지 않습니다. |
| 10·11 | 구형 셸 진단은 과거 구현 설명입니다. 제출본에서는 명령 실행과 실습 파일을 제거했습니다. 파일·인사정보 유출은 가상의 피해이며, 구현상 유지보수 계정 로그인과 관리자 세션 탈취는 다릅니다. |
| 14·18 | 패치 로그인은 계정 잠금이 아니라 **접속 IP별 고정 60초 구간에서 비로그인 POST 10회 허용, 11번째부터 `429`**입니다. |
| 15·18 | 패치 계정 발급·비밀번호 변경에 최소 14자, 흔한 값·숫자 전용·계정 정보와 비슷한 값 금지 정책이 적용됩니다. |
| 16·17 | 패치 사이트는 설정 경로 자체를 제거했습니다. 진단은 별도 권한이 있는 사용자가 등록 호스트의 최신 점검 기록만 조회합니다. |
